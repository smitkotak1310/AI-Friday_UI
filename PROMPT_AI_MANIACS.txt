1. EXECUTIVE SUMMARY
================================================================================

RetailGenie AI is an end-to-end intelligent conversational agent platform
built specifically for retail customer service teams handling high volumes
of repetitive product queries. The system ingests structured product catalog
data (JSON/CSV), understands natural language customer questions using intent
recognition and entity extraction, and delivers accurate, context-aware
responses powered by Azure-hosted LLMs through a sleek React chat widget.

The platform features a conversational AI agent that handles queries about
product details, availability, pricing, and return policies — replacing
rigid FAQ systems and rule-based chatbots with a genuinely intelligent
assistant. It includes live catalog synchronization, sentiment detection,
multi-turn conversation memory, automated escalation to human agents, and
a self-learning feedback loop — all connected to a ChromaDB vector knowledge
base via Haystack RAG pipelines.

The system handles catalog updates dynamically, supports hundreds to
thousands of SKUs, and demonstrates dramatically reduced agent workload
and improved customer satisfaction. Two pre-built synthetic demo scenarios
(Electronics Store + Fashion Retail) showcase diverse query handling
capabilities out of the box.

4. SYSTEM ARCHITECTURE OVERVIEW
================================================================================

[React Frontend] <---> [FastAPI Backend] <---> [SQLite DB]
  (Chat Widget)              |
                    +---------+---------+
                    |                   |
            [Intent/Entity       [Haystack RAG]
             Engine]            [ChromaDB VectorDB]
            [Product Search]    [Azure LLM API]
            [Sentiment Analysis]
                    |
            [Catalog Sync]
            [Escalation Service]
            [Self-Learning]

DATA FLOW:
  1. Customer types a natural language query in chat widget
  2. FastAPI receives message → runs intent classification + entity extraction
  3. Intent determines routing:
     a. Product Info → Product Search engine queries SQLite catalog
     b. Pricing → Direct catalog lookup + promotion check
     c. Availability → Stock status lookup per SKU
     d. Return Policy → Policy document retrieval from ChromaDB
     e. General → RAG pipeline retrieves context + LLM generates response
  4. Haystack RAG retrieves relevant knowledge from ChromaDB
  5. Azure LLM generates natural language response with product context
  6. Sentiment analysis runs on customer message (frustration detection)
  7. If sentiment negative + unresolved → trigger escalation
  8. Response rendered in chat widget with product cards when applicable
  9. Conversation stored in SQLite for analytics and self-learning
  10. Catalog manager uploads new CSV → products synced → embeddings updated

  - Categories: standardized to predefined taxonomy
  - Tags: lowercase, deduplicated
  - Specifications: flatten nested JSON for search indexing
  - Generate searchable_text: concatenation of name + description +

9. MODULE 2: INTENT RECOGNITION & ENTITY EXTRACTION ENGINE
================================================================================

FILE: backend/services/intent_entity_engine.py

CLASS: IntentEntityEngine

--- INTENT CLASSIFICATION ---

INTENT TAXONOMY (6 primary intents):

  1. PRODUCT_INFO
     Triggers: "tell me about", "what is", "describe", "features of",
               "specs", "details", "what does it have"
     Sub-intents: specifications, features, comparison

  2. PRICING
     Triggers: "how much", "price", "cost", "discount", "sale",
               "cheaper", "expensive", "deal", "offer"
     Sub-intents: current_price, sale_check, price_comparison, budget_query

  3. AVAILABILITY
     Triggers: "in stock", "available", "when will", "back in stock",
               "shipping", "delivery", "can I buy", "do you have"
     Sub-intents: stock_check, restock_estimate, shipping_time, pre_order

  4. RETURN_POLICY
     Triggers: "return", "refund", "exchange", "send back", "warranty",
               "defective", "broken", "policy"
     Sub-intents: return_window, return_process, exchange_policy, refund_status

  5. RECOMMENDATION
     Triggers: "recommend", "suggest", "what should I", "best",
               "looking for", "help me find", "compare", "alternative"
     Sub-intents: product_recommendation, budget_recommendation,
                  category_browse, gift_suggestion

  6. GENERAL / OTHER
     Triggers: anything not matching above
     Sub-intents: greeting, complaint, compliment, account_help,
                  order_status, store_info

CLASSIFICATION METHOD:
  PRIMARY: Rule-based keyword matching with fuzzy matching (rapidfuzz)
    - Score each intent based on keyword presence and proximity
    - Confidence = weighted keyword match score

  SECONDARY: Scikit-learn TF-IDF + Logistic Regression classifier
    - Pre-trained on synthetic query dataset
    - Features: TF-IDF vectors of query text
    - Output: intent label + probability distribution
    - Persisted as: backend/models/intent_classifier.pkl

  ENSEMBLE: Weighted combination
    - If rule-based confidence > 0.8: use rule-based (fast path)
    - Else: use ML classifier result
    - If ML confidence < 0.5: classify as "GENERAL" → LLM handles

--- ENTITY EXTRACTION ---

ENTITIES EXTRACTED:
  - product_name: Specific product mentioned ("iPhone 15 Pro")
  - brand: Brand name ("Apple", "Samsung", "Nike")
  - category: Product category ("laptops", "headphones", "dresses")
  - price_mentioned: Numeric price value ("under $500")
  - size: Size specification ("size 10", "XL", "42mm")
  - color: Color mentioned ("blue", "black", "rose gold")
  - sku_id: Direct SKU reference if given
  - attribute: Specific feature ("battery life", "noise cancellation")

EXTRACTION METHOD:
  STEP 1: Regex patterns for structured entities
    - Price: r'\$[\d,]+(\.\d{2})?' or r'under \$?[\d,]+'
    - Size: r'\b(XS|S|M|L|XL|XXL|\d+mm|\d+inch|\d+\s*inch)\b'
    - Color: lookup against predefined color list (50+ colors)
    - SKU: r'\b[A-Z]{2,4}-[\d]{3,6}\b'

  STEP 2: Fuzzy matching against product catalog
    - Extract noun phrases from query
    - Match against product_name, brand, category columns using rapidfuzz
    - Threshold: similarity > 0.75 for product match
    - Return top 3 matches with confidence scores

  STEP 3: SpaCy NER for additional entities
    - PERSON, ORG (brand names), CARDINAL (numbers)
    - Custom-trained entity ruler for retail domain

OUTPUT STRUCTURE (per message):
  {
    "intent": "PRICING",
    "intent_confidence": 0.92,
    "sub_intent": "sale_check",
    "entities": {
      "product_name": {"value": "iPhone 15 Pro", "confidence": 0.95},
      "brand": {"value": "Apple", "confidence": 0.98}
    },
    "matched_products": [
      {"sku_id": "ELEC-IP15P-128", "product_name": "iPhone 15 Pro 128GB",
       "similarity": 0.97}
    ],
    "requires_clarification": false
  }

11. MODULE 4: PRODUCT SEARCH & RETRIEVAL ENGINE
================================================================================

FILE: backend/services/product_search.py

CLASS: ProductSearchEngine

SEARCH METHODS (priority order):

METHOD 1: Exact SKU Lookup
  - If query contains SKU pattern → direct database lookup
  - O(1) lookup, highest precision

METHOD 2: Fuzzy Name Match (rapidfuzz)
  - Compare query noun phrases against product_name column
  - Use token_sort_ratio for word-order independence
  - Threshold: score > 75
  - Return top 5 matches ranked by similarity

METHOD 3: Full-Text Search (SQLite FTS5)
  - Create FTS5 virtual table on:
    (product_name, description, brand, category, tags)
  - Use MATCH operator with query terms
  - Supports phrase matching and boolean operators

METHOD 4: Semantic Vector Search (ChromaDB)
  - Embed product descriptions during catalog indexing
  - Embed customer query
  - Cosine similarity search against ChromaDB
  - Return top 5 results with similarity scores
  - Best for vague/descriptive queries:
    "I need something to listen to music while running"

COMBINED SCORING:
  final_score = (
      fuzzy_score * 0.30 +
      fts_score * 0.30 +
      vector_similarity * 0.40
  )
  Products ranked by final_score, top 5 returned

SEARCH PIPELINE (search_products method):
  1. Extract search terms from query (strip stopwords)
  2. Run all 4 methods in parallel
  3. Merge and deduplicate results
  4. Score and rank
  5. Apply filters from entities (category, brand, price range)
  6. Return structured results with match explanations

OUTPUT:
  [
    {
      "sku_id": "ELEC-IP15P-128",
      "product_name": "iPhone 15 Pro 128GB Natural Titanium",
      "price": 999.00,
      "sale_price": null,
      "availability": "in_stock",
      "match_score": 0.97,
      "match_method": "fuzzy_name",
      "match_explanation": "Exact product name match"
    },
    ...
  ]

CATALOG INDEXING (index_products method):
  Triggered after catalog upload completes:
  1. For each product, create searchable_text:
     "product_name brand category description tags"
  2. Embed searchable_text using Azure text-embedding-3-large
  3. Store embeddings in ChromaDB collection "retail_products"
  4. Populate SQLite FTS5 virtual table
  5. Update catalog_embeddings_log status

SIMILARITY SEARCH FOR RECOMMENDATIONS:
  Given a product, find similar products by:
  1. Same category + similar price range (±20%)
  2. Vector similarity on product descriptions
  3. Filter by availability = in_stock
  4. Return top 5 similar products

ESCALATION TRIGGERS:

  1. SENTIMENT FRUSTRATION
     Trigger: Customer sentiment = "frustrated" for 2+ consecutive messages
     Detection: VADER sentiment analysis + frustration keyword detection
     Keywords: "terrible", "awful", "waste of time", "useless", "ridiculous",
               "never again", "worst", "frustrated", "angry", "fed up"

  2. REPEATED UNRESOLVED QUERY
     Trigger: Same or similar query asked 3+ times without resolution
     Detection: Fuzzy match current query against previous queries in session
     Threshold: similarity > 0.8 across 3 messages

  3. LOW CONFIDENCE STREAK
     Trigger: Intent confidence < 0.3 for 3 consecutive messages
     Indicates: AI doesn't understand what customer wants

  4. CUSTOMER REQUEST
     Trigger: Explicit phrases detected
     Phrases: "talk to human", "speak to agent", "human please",
              "transfer me", "I want a person", "connect me to support"

  5. COMPLEX MULTI-INTENT
     Trigger: 3+ intents detected in single message
     Example: "I want to return my iPhone because it's broken and also
              check if the Samsung Galaxy is in stock and what's your
              warranty policy"

ESCALATION FLOW:
  1. Escalation triggered → create escalation record
  2. Generate handoff summary:
     - Customer sentiment trajectory
     - All products discussed
     - Intents and queries attempted
     - AI responses given
     - Suggested agent response (LLM-generated)
  3. Notify agent via:
     a. In-app notification (AlertBell component)
     b. Real-time dashboard update
  4. Show customer: "I'm connecting you with a specialist who can help.
     One moment please... 🤝"
  5. Agent sees full conversation context in Agent Console
  6. Agent can take over: type responses as "assistant" role
  7. Agent marks conversation resolved

17. MODULE 10: AUTOMATIC RESPONSE QUALITY SYSTEM
================================================================================

FILE: backend/services/quality_checker.py

PURPOSE:
  Automatically evaluate AI response quality and flag poor responses
  for human review and self-learning feedback.

QUALITY CHECKS (run post-generation):

  1. HALLUCINATION CHECK
     - Verify all product names mentioned exist in catalog
     - Verify all prices mentioned match catalog prices (±1%)
     - Verify availability statements match catalog status
     - Flag: "hallucination_risk" if any mismatch detected

  2. RELEVANCE CHECK
     - Cosine similarity between query and response embeddings
     - Threshold: similarity > 0.6
     - Flag: "off_topic" if below threshold

  3. COMPLETENESS CHECK
     - For intent-specific responses, verify required info present:
       PRICING: price mentioned
       AVAILABILITY: stock status mentioned
       RETURN: policy duration mentioned
     - Flag: "incomplete_response" if missing key info

  4. TONE CHECK
     - Sentiment analysis on response
     - Should be positive/neutral, never negative
     - Flag: "inappropriate_tone" if negative sentiment detected

  5. LENGTH CHECK
     - Response should be under 300 words (concise)
     - Flag: "too_long" if exceeded

QUALITY SCORE:
  quality_score = (
      (1 - hallucination_risk) * 0.35 +
      relevance_score * 0.25 +
      completeness_score * 0.25 +
      tone_score * 0.15
  ) * 100

AUTO-REMEDIATION:
  - If quality_score < 50: regenerate response with stricter prompt
  - If quality_score < 30 after retry: escalate to human + flag for review
  - Store quality scores in message record for analytics

HUMAN REVIEW QUEUE:
  - Endpoints: GET /api/quality/flagged
  - Shows messages where quality_score < 60
  - Agent can: approve, edit, or flag as training example
